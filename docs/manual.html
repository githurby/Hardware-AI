Hardware-AI

Find out which AI engines and models your PC can run smoothly — and what to upgrade to run better ones.

What this program does

Hardware-AI detects your CPU, RAM, RAM speed, GPU(s), VRAM and free disk space, then checks a catalog of about 130 AI models (chat, coding, vision, image, video, audio, embeddings) and tells you, for each one:

  • whether it can run, and how well (Smooth Usable Slow Cannot run);
  • how much memory it needs and how big the download is;
  • an estimated speed in tokens per second (for language models);
  • for models that don't fit: the minimum hardware needed and the cheapest upgrade from where you are now.

Everything runs locally; nothing is uploaded. The only network feature is the optional Update models online button.

Getting started

  1. Start Hardware-AI.exe. Detection runs automatically.
  2. Read the Detected hardware panel at the top to confirm it matches your PC.
  3. Click Benchmark RAM once (a few seconds) for much more accurate speed estimates.
  4. Scroll the model list. Green rows are good, red rows cannot run.
  5. Click any model to read its details and requirements in the bottom panel.

Params shows the parameter count. Mixture-of-Experts (MoE) models need memory for all parameters but read only the active ones per token, so they are often faster than their size suggests.

What-if hardware

These fields start with your detected values. Edit them and press Apply to see how the whole list changes.

  • CPU cores — physical cores used for CPU inference.
  • RAM (GB) — total system memory (3 GB is reserved for Windows).
  • RAM GB/s — memory bandwidth, the main driver of CPU speed. Leave blank for an estimate from your RAM type, or use Benchmark RAM for a measured value.
  • VRAM (GB) — graphics memory.
  • GPU preset — pick a real card (RTX 4060, 4090, 5090, RX 7900 XTX, Arc…) to fill VRAM and GPU bandwidth. "No GPU" simulates CPU only.
  • Reset to detected — go back to your real hardware.
  • Sum all GPUs — adds the VRAM of several dedicated GPUs (integrated GPUs under 1 GB are ignored).
Multi-GPU noteSummed VRAM assumes the engine can split a model across cards (llama.cpp does). Speed with mixed or PCIe-limited cards can be lower than estimated.

Working with the list

  • Click a column header to sort; click again to reverse. Sort by Est. tokens/s to find the fastest model, or by Download to find the smallest.
  • Single click a row: shows full details and requirements below.
  • Double-click a row: adds/removes it from your favorites (marked with *). Favorites are saved.
  • Row colors follow the result level, in both light and dark themes.
  • If your disk is too small for a model's download, the details panel warns you.

Buttons & tools

Re-detect

Scans the hardware again (use after installing a GPU or RAM) and discards manual changes.

Benchmark RAM

Reads a large block of memory with several threads to measure real bandwidth in GB/s. The result replaces the estimate everywhere. Close heavy programs first for a true reading. Typical values: older DDR2/DDR3 desktops 5–20, dual-channel DDR4 30–50, DDR5 60–90, workstation/server 100+.

Export report

Saves a text file with your hardware, the settings used, and the full model table — handy for forum posts or hardware shopping lists.

Save profile / Load profile

Stores your what-if setup (.hwai file: cores, RAM, bandwidth, VRAM, GPU, quant, context). Make profiles like "Current PC", "After RTX 4060 Ti 16GB", "Dream workstation" and switch between them in one click.

Copy run command

Select a language model that fits, then click. A ready llama-server command is copied to the clipboard, with context size, threads, GPU layers (-ngl), flash attention, and for MoE models the trick of keeping expert weights in RAM. Replace the model file name with your downloaded .gguf path.

llama-server -m "Qwen3 8B-Q4_K_M.gguf" -c 4096 -t 4 -ngl 99 -fa

Online updates

Update models online downloads models-online.csv from the project's GitHub repository, saves it to %APPDATA%\Hardware-AI and adds any new models immediately. It is loaded again automatically at every start. If you are offline you'll get a message and nothing changes. "Already up to date" means no new names were found.

Tips & tricks

1. Run the RAM benchmark firstCPU speed is almost entirely RAM bandwidth. A measured value beats any estimate.
2. Memory bandwidth beats core countFaster RAM (or dual-channel) speeds up CPU inference more than extra cores. Check that both sticks are in the correct slots.
3. Try lower quant or shorter contextSwitching Q8 → Q4_K_M, or 32K → 4K, can turn Cannot run into Usable without spending anything.
4. MoE models are a hidden gemModels marked (MoE) need lots of RAM but read few parameters per token. With plenty of RAM they can beat dense models of the same size.
5. VRAM is kingA model fully inside VRAM (GPU mode) is far faster than any GPU+CPU split. When shopping, prefer more VRAM over a slightly faster chip.
6. Plan upgrades with presetsChoose a GPU preset, add RAM in the what-if box, press Apply, and watch how many rows turn green. Use Compare with to see current vs. planned side by side, and save each plan as a profile.
7. Sort to find your best modelHide "Cannot run", sort by Est. tokens/s descending, and choose the biggest model that is still Smooth or Usable.
8. Check the budget linesThe cheapest-upgrade section lists rough prices and the minimum power supply for the GPU tier. Prices are estimates — verify locally.
9. Free disk spaceLarge models are tens or hundreds of GB. Watch the Download column and the disk warning.
10. Where to run themLanguage models: llama.cpp, Ollama or LM Studio. Images/video: ComfyUI or Forge. Speech: whisper.cpp, Piper, XTTS. The details panel names the right one, with the backend for your GPU (CUDA, Vulkan, ROCm, SYCL).

Troubleshooting

ProblemSolution
VRAM is wrong or shows 0Integrated or very old GPUs may report incorrectly. Type the real value in VRAM (GB) or pick a preset, then Apply.
RAM speed or GB/s not shownSome PCs don't expose memory info. Use Benchmark RAM, or type a value.
Benchmark says not enough memoryClose other programs and try again.
A model I know is missingAdd it in models.csv, or try Update models online.
Estimate differs from my real speedEstimates are approximate. Engine, drivers, thermal throttling, background apps and quantization all matter. Use them for comparison and planning, not as a guarantee.
Online update failsCheck internet/firewall. The program keeps working offline with the last saved list.
Reset everythingDelete the registry key HKEY_CURRENT_USER\Software\Hardware-AI (favorites, theme, language) and the folder %APPDATA%\Hardware-AI.

How the estimates work

  • Memory needed = weights (parameters × bytes per parameter for the chosen quant) + KV cache for the chosen context + a small overhead.
  • Speed ≈ memory bandwidth × efficiency ÷ data read per token. GPU uses VRAM bandwidth, CPU uses RAM bandwidth, partial offload mixes both by the share of the model on each side.
  • Thresholds: Smooth ≥ 15 tok/s, Usable ≥ 5 tok/s.
  • System reserve: 3 GB of RAM is kept for Windows.
  • Model sizes, active parameters and upgrade prices are the author's estimates and may differ from real files.
